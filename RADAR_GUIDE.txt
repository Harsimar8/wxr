PART 2 - HOW MY APP GETS DATA FROM FLIGHTGEAR
==============================================================================

FlightGear keeps EVERY value in a big tree called the "property tree".
Example:  /position/altitude-ft  = 3500
You can see it all in FlightGear:  Debug > Browse Internal Properties

There are 3 ways to take data out:

  1) GETTING  (telnet, fg_link.py)
     The app asks: "give me /orientation/heading-deg"  -> FlightGear answers.
     Good for: simple values that are already in the property tree.

  2) SCRIPT   (Nasal, wxradar_export.nas)
     A small program that runs INSIDE FlightGear. It collects data that is
     hidden inside FlightGear's own code and copies it to /wxradar/...
     The app then GETS it from there.
     Good for: data NOT in the property tree, big lists, heavy work.
     My script now exports:
        - weather volumes  -> /wxradar/volumes   (rain, snow, turb, base, top)
        - terrain grid     -> /wxradar/terrain   (height + land/water)
        - placing storms   -> /wxradar/place

  3) UDP OUTPUT  (generic protocol, XML file in fgdata/Protocol)
     FlightGear PUSHES values to the app many times a second.
     Good for: values that change every frame (pitch, roll). Smooth.

RULE OF THUMB
  - Value is in the property browser       -> GET it
  - Value is only inside Nasal code / big   -> SCRIPT it
  - Value changes every frame               -> UDP

PART 3 - WHAT WINDSHEAR / MICROBURST IS
==============================================================================

Windshear = the wind changes a lot over a short distance.

The dangerous kind is a MICROBURST. Under a heavy rain storm, cold heavy air
falls straight down, hits the ground and splashes out in all directions,
like water poured from a bucket.

                      THUNDERSTORM
                 +------------------+
                 |  rain + cold air |
                 +------------------+
                      |  |  |  |          (1) DOWNDRAFT
                      v  v  v  v              air falling 10-20 m/s
                      v  v  v  v
       <<<<<<<<<<<<<<<<<< * >>>>>>>>>>>>>>>>>>   (2) OUTFLOW
     ====================== GROUND ======================
     (3) gust front                       (3) gust front

Parts:
  (1) Downdraft  - air falling 10-20 m/s, 1-2 km wide
  (2) Outflow    - air spreading out 15-25 m/s, strongest 100-300 ft high
  (3) Gust front - outer edge, gusty, colder
  (4) Ring/roll  - air curling up at the edges -> turbulence

Size under 4 km, lives 5-15 minutes.
  WET microburst = with heavy rain  -> radar CAN see it
  DRY microburst = almost no rain   -> radar can NOT see it (very dangerous)

What the plane feels:

  plane ->  HEADWIND        ->  DOWNDRAFT    ->  TAILWIND
            speed goes UP       pushed DOWN      speed DROPS suddenly
            plane floats                         plane sinks -> CRASH RISK

Only dangerous LOW DOWN (takeoff / landing): no height left to recover.

PART 4 - HOW A REAL RADAR FINDS WINDSHEAR
==============================================================================

Not every radar can. It needs a DOPPLER radar with the PWS option
(e.g. Collins WXR-2100, Honeywell RDR-4000 on 737NG/MAX, A320, 777, 787).
Small planes' radars cannot.

Step 1  Radar sends a beam ahead (5 NM, +/-40 deg), only below 2300 ft.
Step 2  The beam hits RAINDROPS and bounces back.
Step 3  DOPPLER (like an ambulance siren: higher pitch coming, lower going):
          echo higher  -> drops coming TOWARD the plane
          echo lower   -> drops going AWAY from the plane
        Drops move with the wind, so the radar MEASURES THE WIND.
Step 4  Look for the pattern along one beam:
          1 NM: drops coming at me  (+15 m/s)
          2 NM: drops still         (0)
          3 NM: drops going away    (-15 m/s)
        Turn it into a number: F-FACTOR
          F = (how fast tailwind grows) / g  -  (downdraft) / airspeed
        F above 0.13 (over about 1 km) = DANGER
Step 5  Warn:
          amber WINDSHEAR  "Monitor radar display"   (3-5 NM or to the side)
          red   WINDSHEAR  "Go around, windshear ahead"  (landing)
                           "Windshear ahead, windshear ahead" (takeoff)
                           (within 3 NM and +/-25 deg)

Height rules:
  above 2300 ft      -> off
  1200 - 2300 ft     -> icon only, no text, no voice
  below 1200 ft      -> icon + text + voice

Other windshear systems in real planes:
  - REACTIVE windshear (in GPWS): warns when ALREADY INSIDE it, from the
    plane's own airspeed drop and sink. Says "WINDSHEAR WINDSHEAR WINDSHEAR".
  - Airport ground systems (LLWAS sensors, TDWR radar): ATC warns pilots.


==============================================================================
PART 5 - HOW MY APP FINDS WINDSHEAR
==============================================================================

Same 5 steps, but Step 3 is different:

  Step | Real radar                      | My app
  -----+---------------------------------+--------------------------------------
   1   | beam 5 NM ahead +/-40 deg       | same      (radar.py windshear())
   2   | echo from drops                 | reads rain from FlightGear
   3   | MEASURES wind with Doppler      | BUILDS the wind itself (model)
       |                                 |   (weather.py outflow())
   4   | F-factor > 0.13                 | same maths (radar.py _f_factor_hazard)
   5   | wedge + text + voice            | same (display.py _draw_pws,
       |                                 |       main.py _update_pws)

When does my app make a microburst?

  REALISTIC mode (FlightGear volumes):
    A volume gets a microburst under it only if ALL are true:
      - rain-flag = 1
      - shape is circle or ellipse (not rectangle)
      - rain above 0.5
    Strength = 20 m/s x (how much rain is above 0.5) x (0.6 + 0.4 x turbulence)
    More rain + more turbulence = stronger. Weak ones may not reach F 0.13.

  SIMPLE mode:
    rain 45 dBZ or more AND turbulence 0.6 or more at 500 ft = windshear.

  TEST button: "Add microburst ahead" puts a strong cell 3.5 NM ahead
  (built-in weather only, switched off when FlightGear weather is used).

So: no strong rain volume  ->  no windshear.

What my model has:      downdraft, outflow, strongest low down, needs rain,
                        turbulence makes it stronger
What it does not have:  cold air, ring/roll, life cycle (grow and die),
                        separate microburst you can place, dry microburst


==============================================================================
PART 6 - WHY FLIGHTGEAR CANNOT GIVE US WINDSHEAR
==============================================================================

FlightGear's Detailed Weather is made of WEATHER VOLUMES: invisible shapes in
the sky (circle, ellipse or box). Each one only has numbers:

     position, size, shape, base height, top height
     rain        0..1
     snow        0..1
     turbulence  0..1
     visibility
     lift        (gentle up-air for gliders)

It is like a ROOM WITH A SIGN on the door: "inside: rain 0.8, turbulence 0.6".
When your plane goes in, FlightGear switches on rain and shaking.

FlightGear wind = ONE value, at the plane only:
     /environment/wind-from-heading-deg
     /environment/wind-speed-kt

A microburst needs a DIFFERENT WIND AT EVERY POINT (down in the middle, out
to the left, out to the right). FlightGear has nothing like that, so:
  -> the app must BUILD the microburst wind itself
  -> the plane in FlightGear does NOT really sink or lose speed in it
     (only our radar warns). This can be fixed - see PART 7 / PART 10.

PART 7 - WAYS TO CHANGE / USE FLIGHTGEAR MYSELF
==============================================================================

YES, I can change FlightGear. 4 levels, easy -> hard:

  1) NASAL SCRIPTS  (EASIEST, BEST)
     - Text files (.nas), no compiling, just restart FlightGear.
     - I already do this: wxradar_export.nas
     - Can READ anything inside FlightGear and WRITE values
       (e.g. set the wind on the plane to make it feel a microburst).
     - FlightGear's weather code is Nasal too:
         ...\fgdata_2024_1\Nasal\local_weather\
     - Do NOT edit FlightGear's own files. Keep my code in MY .nas file,
       so a FlightGear update does not delete it.
     - Test ideas fast: Debug > Nasal Console (no restart).

  2) PROPERTY TREE  (no FlightGear change at all)
     - Read / write any value from Python over telnet (fg_link.py).

  3) XML FILES  (settings only)
     - AI scenarios (AI storms, thermals), protocols (UDP), cockpit screens.

  4) C++ SOURCE  (HARDEST, NOT NEEDED)
     - Must download and compile FlightGear. Hours of setup on Windows.
     - Nasal can do almost everything I need.

Drawing shapes / images:
  - On MY radar screen: display.py with QPainter (lines, circles, polygons,
    text, PNG images). Write a new _draw_xxx(p) function and add one line
    next to self._draw_pws(p). Easiest place to start.
  - Inside FlightGear: "Canvas" (Nasal) for cockpit screens / popups,
    3D models (Blender .ac + XML) for objects in the sky. Harder.

PART 11 - BEST WAY TO RUN FLIGHTGEAR FOR THIS PROJECT
==============================================================================

SETUP A - fly in FlightGear itself (best for testing)

  1. Launcher > Settings > Additional Settings:
        --telnet=5401
        --disable-real-weather-fetch
        --disable-ai-traffic
        --disable-random-buildings
        --disable-random-vegetation
        --fog-fastest
  2. Environment > Weather > DETAILED WEATHER (not Basic)
     Tile: "Thunderstorms" or "Cold front" for storms, "Fair weather" to
     check nothing false appears. Click Apply.
  3. Put wxradar_export.nas in ...\fgdata_2024_1\Nasal\  (loads at start).
  4. Aircraft: 737-800 / A320 (real approach speeds), Cessna 172 (easy,
     slow), UFO (move anywhere fast to look at storms).
  5. Keep FlightGear at 25+ FPS (app shows FPS green/amber/red).

SETUP B - FlightGear only as weather for another simulator
  Use the options in README.md (--fdm=null, --generic=...wxradar-in, etc.)

Useful FlightGear tools
  Debug > Browse Internal Properties  - see every value live
  Debug > Nasal Console               - run Nasal without restart
  Environment > Weather               - change storms live
  Environment > Time Settings         - daytime, to see clouds
  P key                               - pause and compare radar with clouds

Routine
  1. Start FlightGear  2. Detailed Weather > Thunderstorms > Apply
  3. Start app > Connect  4. Check volumes on radar
  5. Fly toward a red cell at about 800 ft  6. Watch for WINDSHEAR

First thing to check if the radar shows nothing:
  Property browser > /wxradar/volumes/count
  If 0 -> export script not running, or Detailed Weather is off.
